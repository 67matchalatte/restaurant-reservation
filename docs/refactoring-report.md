# Отчет о рефакторинге (SOLID)

## 1. Нарушение принципа единственной ответственности (SRP)
**До:** В файле `app.py` находилась и маршрутизация Flask, и прямая работа с базой данных (SQL-запросы), и бизнес-логика (проверка занятости столика).
**После:** Код разделен на три слоя:
- `db.py` — отвечает только за подключение к SQLite и запросы к таблицам.
- `services.py` — отвечает только за бизнес-логику (валидация, проверка занятости, транзакции).
- `app.py` — отвечает только за обработку HTTP-запросов и рендеринг шаблонов.

Это позволяет изменять логику работы с БД, не затрагивая маршруты, и наоборот.

## 2. Внедрение паттерна «Стратегия»
В файле `services.py` внедрен паттерн «Стратегия» для отправки уведомлений о создании брони.
Выбор паттерна обоснован тем, что в будущем ресторан может захотеть отправлять уведомления не только через SMS, но и на Email или в Telegram. Благодаря паттерну, для добавления нового способа уведомления достаточно создать новый класс, реализующий интерфейс `NotificationStrategy`, не меняя основной код функции `create_booking`.
