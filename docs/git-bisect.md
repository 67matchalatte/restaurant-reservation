# Демонстрация работы git bisect

Для отработки навыка поиска дефектов (методичка ЛР-6, Шаг 10) была смоделирована ситуация, когда в проект был добавлен коммит, ломающий тесты.

## Шаги поиска дефекта:
1. Изначально проект находился в стабильном состоянии (все тесты `pytest` проходили).
2. Было сделано несколько коммитов (добавление комментариев и документации), среди которых один коммит намеренно нарушал работу приложения (например, удалял импорт `os` в `app.py`).
3. Для поиска виновного коммита был запущен **git bisect**:
   - `git bisect start`
   - `git bisect bad` (текущее состояние сломано)
   - `git bisect good v0.1.0` (последний известный стабильный тег)
4. Git автоматически переключил проект на коммит посередине истории. Мы запустили тесты (`pytest`), они упали. Ввели команду `git bisect bad`.
5. Git переключил на коммит ниже. Тесты прошли успешно. Ввели `git bisect good`.
6. Процесс повторялся (бинарный поиск), пока Git не выдал: `xxxxxxx is the first bad commit`.
7. Мы увидели, какой именно коммит сломал код, и откатили его.
8. Завершили поиск командой `git bisect reset`.
