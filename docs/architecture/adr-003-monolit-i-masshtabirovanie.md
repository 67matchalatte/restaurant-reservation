# ADR-003: Монолитная архитектура для учебного проекта

**Статус:** принято (21.10.2026)

## Контекст
- Команда 3 человека, срок семестра.
- АЗТ-3: доступность ≥ 99% в часы работы.
- Нет требований к независимому масштабированию частей системы.

## Решение
Строить **монолит**: один API-сервер (Flask) + SPA-фронтенд + одна БД.
Все модули (каталог, бронь, админ) — в одном приложении, разбиты на пакеты.

## Отвергнутые альтернативы
- **Микросервисы:** избыточны для 3 человек и 20 столиков; сложность оркестрации, сетевых вызовов и отладки не оправдана.
- **Serverless:** ограничения по времени выполнения и сложность локальной разработки.

## Последствия
- (+) Простота разработки, отладки, развёртывания; один репозиторий.
- (−) Масштабирование только целиком (вертикальное); при росте — выделение модуля брони в сервис (риск принят, см. ADR-004 — план).
- Доступность 99% достигается за счёт одного сервера с автоперезапуском (systemd/Docker restart).
