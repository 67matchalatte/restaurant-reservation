# ADR-001: Хранилище — SQLite на первый релиз (MVP)

**Статус:** принято (21.10.2026)

## Контекст
- АЗТ-1: каталог ≤ 2 с при 1000 записей.
- АЗТ-2: до 50 одновременных запросов.
- Один сервер, один ресторан (до 20 столиков) — по интервью ЛР-4.
- Команда из 3 человек, срок MVP — неделя 8.

## Решение
Использовать **SQLite** как хранилище для релиза v0.1 (MVP).
Альтернатива **PostgreSQL** отклонена: не нужны соединения извне на первом релизе, избыточна для одного сервера и 20 столиков.

## Отвергнутые альтернативы
- **PostgreSQL:** избыточен для MVP; миграция возможна позже (см. ADR-002).
- **Файловое хранение JSON:** не даёт транзакционности проверки занятости (риск двойной брони).

## Последствия
- (+) Простота развёртывания, нулевая настройка, быстрый старт.
- (−) При многопользовательском кабинете организатора потребуется миграция на PostgreSQL (риск принят, см. ADR-002 — план миграции).
- Транзакции SQLite достаточны для 50 одновременных запросов при правильной настройке WAL.
