# Правила работы над проектом

## Ветвление

- Основная ветка — `main`. Прямые коммиты в `main` запрещены.
- Любое изменение — в отдельной ветке с осмысленным именем:
  - `feature/<название>` — новая функциональность;
  - `docs/<название>` — документация;
  - `fix/<название>` — исправление ошибки.
- Ветка живёт до слияния в `main`, после слияния удаляется.

## Коммиты

- Сообщение коммита — в повелительном наклонении, по делу:
  - «Добавить форму брони»
- Коммит должен решать одну задачу; большие изменения дробятся на серию коммитов.

## Pull request

- Любое изменение попадает в `main` только через pull request.
- В PR обязательно: заголовок в повелительном наклонении, описание
  (что сделано, зачем, как проверить), назначенный ревьюер.
- Ревьюер проверяет изменения и ставит **Approve** или **Request changes**.
- Только после Approve PR сливается в `main`.

## Роли и ротация

- Стартовые роли: тимлид, аналитик, разработчик.
- Роли ротируются в течение семестра — каждый участник должен
  побывать минимум в двух ролях.

## Встречи

- Планёрка — раз в неделю, 15 минут.
- Протокол встречи — в `docs/protocols/`.
- Задачи — в трекере (GitHub Projects), а не в чате.
